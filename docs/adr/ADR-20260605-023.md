# ADR-023: Codex 組み込み image_gen による画像生成サブエージェントの追加

- **ステータス**: accepted
- **日付**: 2026-06-05
- **決定者**: yoshihiko
- **関連**: なし（新規機能）

## コンテキスト

Claude Code から手軽に画像を生成したい。現状、画像生成は Adobe Firefly などの外部ツールで行っているが、README 用の図やちょっとしたビジュアルなど「簡単な画像」であれば、Claude Code のワークフロー内で完結できると楽になる。

調査の結果、Codex CLI（`0.137.0`）には `~/.codex/skills/.system/imagegen/` という**システム組み込みスキル**が存在し、`image_gen` ビルトインツール経由で OpenAI の画像生成（`gpt-image` 系）を呼び出せることが判明した。これを Claude Code から呼び出す仕組みを整える。

### 実機検証で判明した事実（2026-06-05）

- Codex の組み込み `image_gen` は **Codex の ChatGPT 認証**で動作し、`OPENAI_API_KEY` は不要。
- 一方、同梱の `image_gen.py` を直接叩く CLI フォールバックは `OPENAI_API_KEY` 必須（OpenAI Images API 直呼びで課金発生）。**本プロジェクトでは API キーを使わない**方針のため、これは不採用。
- 非対話 `codex exec` から組み込み `image_gen` を呼ぶには **sandbox の二層構造**を解く必要がある（下記）。
- 過去に `~/.codex/generated_images/` へ生成された画像は本物の AI 生成（高品質）であることを目視確認済み。
- レートリミット（`TooManyRequests`）は短時間の連打由来であり、恒常的な制限ではない。1 タスク 1 回の呼び出しなら発生しない。

### sandbox の二層構造（本 ADR の中核）

| 層  | 対象                        | 画像生成での扱い                                                                                                                                 |
| --- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 層1 | Claude Code の Bash sandbox | **無効化が必須**（`dangerouslyDisableSandbox: true`）。有効なままだと Codex の in-process app-server 起動が `Operation not permitted` で失敗する |
| 層2 | Codex 自身の `--sandbox`    | **通常の `workspace-write` で十分**。`--dangerously-bypass-approvals-and-sandbox` は不要                                                         |

当初は層2 のフルバイパス（`--dangerously-bypass-approvals-and-sandbox`）が必要と考えたが、実機検証で「層1 を無効化すれば層2 は通常の `workspace-write` のままで本物の AI 画像を生成できる」ことが確定した。これによりセキュリティリスクを通常の実装エージェント（`ai-dev` 等）と同等まで圧縮できる。

## 検討した選択肢

### 選択肢 A: `image_gen.py` 直叩き（CLI フォールバック）

- 流れ: `python ~/.codex/skills/.system/imagegen/scripts/image_gen.py generate --prompt ... --out ...`
- メリット: 非対話で確実に動く、出力先を引数で自由指定可
- デメリット: **`OPENAI_API_KEY` 必須・OpenAI Images API 課金**。API キーを使わない方針に反する → 不採用

### 選択肢 B: 対話モード駆動（PTY/expect）

- 流れ: `codex` を対話起動し、PTY 経由で自然言語指示を流し込む
- メリット: API キー不要
- デメリット: 実装が複雑かつ脆い（プロンプト待ち検出・タイムアウト処理）→ 不採用

### 選択肢 C: `codex exec` + 組み込み image_gen（本 ADR の採用案）

- 流れ: Claude Code 側 Bash を `dangerouslyDisableSandbox: true` で実行し、`codex exec --model gpt-5.5 --sandbox workspace-write --skip-git-repo-check --full-auto "Generate ... Save to <path>"` を呼ぶ
- メリット: **API キー不要**（ChatGPT 認証）、本物の AI 生成、危険フラグ不要、出力先をプロンプトで指定可
- デメリット: 層1 無効化（`dangerouslyDisableSandbox`）が必要、`gpt-5.5` 固定が必要、レートリミット時に Codex が Pillow 代替描画する挙動への対処が要る

## 決定

**選択肢 C** を採用する。

### 確定した呼び出し契約

```bash
# Claude Code 側 Bash は dangerouslyDisableSandbox: true で実行（層1 無効化）
codex exec \
  --model gpt-5.5 \
  --sandbox workspace-write \
  --skip-git-repo-check \
  --full-auto \
  "Generate <subject>. Save the file to <abs-path>. \
   Do NOT fall back to drawing the image programmatically (Pillow/ImageMagick) \
   if image generation fails due to rate limits; report the failure explicitly instead."
```

### 確定した設計判断

1. **モデルは `gpt-5.5` 既定**。`codex.model`（`gpt-5.3-codex`）は ChatGPT アカウントで image_gen 非対応のため流用できない。`packages/image-generation/config/image-generation.yaml` の `image_model` キーで指定し、差し替えを容易にする。
2. **層1 無効化は画像生成コマンドに限定**。`image-generator` エージェントは既存エージェントの「`dangerouslyDisableSandbox` は使用しない」方針を、画像生成 Bash 実行に限り意図的に上書きする。それ以外の操作では sandbox を維持する。
3. **Pillow フォールバックは失敗扱い**。レートリミット時に Codex が Pillow で描いた非 AI 画像を返すことがあるため、プロンプトで禁止指示を埋め込み、かつ出力テキスト/セッションログで検知して警告・失敗として扱う。
4. **レートリミット対策は 1 タスク 1 回**。連打を避ける。
5. **出力先デフォルトは `generated-images/`**（リポジトリ直下、`.gitignore` 管理）。プロンプト/引数で任意パス指定可。

### 成果物の配置

**設計改訂（2026-06-05、Codex 相談を経て）**: 当初は `image-generator` を agent-routing の `cli-tools.yaml` / `route_config.py` に登録する案だったが、(a) エージェント自身が `codex exec` を直接叩くため通常の codex-delegation 経路に乗らずルーティング登録が冗長、(b) 登録すると整合性テストの制約でエージェント定義が agent-routing パッケージに同居せざるを得ず、`packages/image-generation` が hollow shell 化する、という 2 点から廃止した。エージェントは Claude Code のネイティブ subagent dispatch（description ベース）＋ `/image-gen` スキルからの明示 `Task()` で起動する。これにより image-generation は `core` のみ依存の自己完結パッケージになる。

| 要素                           | 配置                                                                                                           |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `/image-gen` スキル            | `facets/instructions/image-gen.md` + `facets/compositions/skills/image-gen.yaml` → `orchex facet build` で生成 |
| `image-generator` エージェント | 新規 `packages/image-generation/agents/image-generator.md`                                                     |
| パッケージ定義                 | 新規 `packages/image-generation/manifest.json`（depends: **core のみ** / 自己完結）                            |
| モデル設定                     | `packages/image-generation/config/image-generation.yaml` の `image_model`                                      |
| 起動経路                       | ネイティブ subagent dispatch ＋ `/image-gen` スキルからの明示 `Task()`（独自ルーティング登録なし）             |

## 影響

### コードベース変更

- 新規 `packages/image-generation/`（manifest, agents/image-generator.md, config/image-generation.yaml, README）
- 新規 `facets/instructions/image-gen.md`, `facets/compositions/skills/image-gen.yaml`
- `packages/agent-routing`: ルーティング登録は行わない（cli-tools.yaml / route_config.py は不変更）
- `.gitignore`: `generated-images/` 追加
- `docs/adr/DECISIONS.md`: 本 ADR を追加

### 運用への影響

- `/image-gen <プロンプト>` で画像生成、または「画像生成して」等の依頼で Claude が `image-generator` サブエージェントをネイティブに選択して起動。
- 画像生成時のみ Codex 実行 Bash が sandbox 無効で走る（`image-generator` エージェント内に限定）。

## 残余リスク

- **`gpt-5.5` のアカウント/将来非対応**: ChatGPT 認証が前提。モデルは `image_model` キーで config 化し差し替え可能にした。
- **レートリミット**: 連打で発生。1 タスク 1 回で緩和。検知時はユーザーに報告。
- **Pillow フォールバック混入**: プロンプト禁止指示 + 出力検知の二段で防ぐが、検知漏れの可能性はゼロではない。生成後にユーザーが目視確認することを推奨。
- **`dangerouslyDisableSandbox` の常用**: 画像生成コマンドに限定し、汎用化しない。セキュリティレビューで限定範囲を確認する。

## Update（2026-06-17）: codex 0.140.0 での呼び出し契約の改訂

codex-cli が **0.140.0** に更新され、上記「確定した呼び出し契約」が機能しなくなったため改訂する（原契約は履歴として残す）。実機検証（task/image-gen-bug）で確定した事実:

1. **`--sandbox workspace-write` だけでは app-server が起動しない**。`image_gen` の in-process app-server が backend へ通信するため、Codex 層2 の **network が遮断**されていると `failed to initialize in-process app-server client: Operation not permitted (os error 1)` で失敗する。→ `-c sandbox_workspace_write.network_access=true` で **network だけ開放**する。FS は `workspace-write` のまま repo 内に OS 強制で限定され、`danger-full-access` / `--dangerously-bypass-approvals-and-sandbox` は**使わない**（untrusted prompt で呼ばれ得るため OS 境界を維持）。
2. **`--full-auto` は deprecated**（`--sandbox` に統合）。削除する。
3. **保存先は指定パスに従わない**。`image_gen` は常に `~/.codex/generated_images/<session>/ig_*.png` に保存する（プロンプトの "Save to `<path>`" は無視）。エージェントは**生成直前のマーカー時刻より新しい**ファイルのみを採用し出力先へコピーする（**鮮度ガード**: 過去の画像を誤って成功扱いする不具合を防ぐ）。
4. **agentic codex の自己検閲**。高い reasoning では Codex が生成画像を品質評価して勝手に破棄することがある。`-c model_reasoning_effort=low` で抑制し、プロンプトで「品質で拒否するな/削除するな」を明示する。

改訂後の呼び出し契約:

```bash
# Claude Code 側 Bash は dangerouslyDisableSandbox: true で実行（層1 無効化）
codex exec \
  --model gpt-5.5 \
  --sandbox workspace-write \
  -c sandbox_workspace_write.network_access=true \
  -c model_reasoning_effort=low \
  --skip-git-repo-check \
  "Use your built-in image_gen tool to generate <subject>. Accept whatever it returns; \
   do NOT delete files. Print the saved path. Do NOT fall back to Pillow/ImageMagick on \
   rate limit; report failure explicitly." < /dev/null
```

詳細は `packages/image-generation/agents/image-generator.md` の Sandbox Policy / Step 3 / Step 3.5 を正本とする。
