# ADR-20261027-059: Plans.md を Project ごとの plan ファイル `.claude/plans/<slug>.md` に分割する（ADR-056 / 058 の部分 supersede）

- **ステータス**: accepted
- **日付**: 2026-10-27
- **決定者**: yoshihiko
- **関連**: ADR-20260926-056（§決定 2 の「Plans.md v2」のうち、発注書と状態を 1 本の `.claude/Plans.md` に
  まとめて持つ部分と、Decisions / Notes をファイル末尾に 1 つずつ持つ部分を部分 supersede。Project → Phase →
  Task の階層、5 節、AC を Phase の属性とする決定、発注書を 1 エンジン 1 か所に置く決定は有効のまま）、
  ADR-20260928-058（「hook は読むだけ」は維持。§影響の「完了した Project は Plans.md に残り、Goal の注入も
  続く」「root で使い回す場合は手動で消す」を本 ADR の注入対象の絞り込みと `/task-state close` に置き換える）、
  Issue #521（旧 `.claude/Plans.md` の扱いの完全廃止）
- **codd 注記**: codd グラフ上は ADR-20260926-056 / ADR-20260928-058 への依存を `references` とする
  （codd の `supersedes` は全体置換の意味論のため。実際の変更範囲は「決定」節参照）

## コンテキスト

発注書と状態は 1 本の `.claude/Plans.md` に Project を並べて持っていた（ADR-20260926-056）。worktree で
作業するなら 1 worktree = 1 タスクで、Plans.md も worktree と一緒に消える。一方、worktree を切らずに 1 本の
ブランチや root で作業を続けると、Project が積み重なってファイルが肥大化する。ADR-20260928-058 で
自動アーカイブを廃止したため、完了した Project も消えずに残る。

1 本のファイルであることが、次の問題を生んでいた。

- **注入が混ざる**: SessionStart はタスクを全 Project 混ぜた 1 リストで注入し、どのタスクがどの Project の
  ものかを出さない。表示上限（既定 20）も全 Project で共有する
- **完了した Project が注入され続ける**: Goal が載り続け、片付けの手段は手動編集しかない
- **Decisions / Notes がどの Project にも属さない**: ファイル末尾に 1 つずつで、Project を Issue に出したり
  消したりしても切り離せない

## 検討した選択肢

### 選択肢 A: Plans.md は 1 本のまま、完了した Project を片付ける手段（`/task-state archive` 等）を足す

- メリット: 変更が小さい。既存の配布先がそのまま動く
- デメリット: 同時に進む複数の Project が 1 ファイルに混ざる問題は残る。注入の混在も Decisions / Notes の
  帰属も解決しない

### 選択肢 B: Project ごとに、計画書（Markdown）と状態（JSON）の 2 ファイルに分ける

- メリット: 状態を機械が確実に読める
- デメリット: AC の定義とチェックが別ファイルになる。`/handoff` で Codex に渡すファイルが 2 つになる。
  状態を書き換えるのは主に Claude と Codex で、JSON は 1 文字の誤りで全体が読めなくなる。既存のパーサを
  作り直すことになる

### 選択肢 C: Project ごとに Markdown 1 ファイル（`.claude/plans/<slug>.md`）に分ける

- メリット: いまの Project の構造をそのまま切り出せる。注入をファイル単位にまとめられ、完了したファイルを
  注入から外して片付けの単位にもできる。codd の「1 ファイル = 1 ノード」とも対応する
- デメリット: Plans.md を読み書きする箇所（hook 3 つ・スキル・scaffold・`.gitignore`・codd・テスト・
  評価セット・ドキュメント）をすべて直す必要がある

## 決定

**選択肢 C** を採用する。旧 `.claude/Plans.md` との後方互換は持たず、移行コマンドも作らない（既存の
Plans.md は利用者が整理する）。

- **単位と置き場所**: 1 Project = Markdown 1 ファイル `.claude/plans/<slug>.md`（平置き、git に入れない）。
  slug は Project 名から作る `[a-z0-9][a-z0-9-]*`。書式は従来の Project（5 節 + Phase の AC と Tasks）で、
  Decisions / Notes はファイルごとに持つ
- **完了の判定**: タスク（`cc:` 行）が 1 件以上あり、すべて `cc:done` で、AC がすべてチェック済みのファイル
- **SessionStart の注入**（`load-task-state.py`）: 未完了のファイルをファイルごとにまとめて全部注入する。
  WIP を持つファイルを先に、同順位はファイル名順に並べる。表示上限は全ファイルで共有し、上限を超えた
  ファイルは件数だけの 1 行に縮める。完了したファイルは件数だけ出し、`/task-state close` を案内する。
  hook は読むだけ（ADR-058 を維持）
- **PreCompact と Stop**: PreCompact の退避ファイルには要約とパスを書き、全文は写さない。Stop の要約は
  未完了のファイルを合計した件数にする
- **片付け**: `/task-state close <slug>` が、完了しているか確認し、Decisions のうち後から参照するものを
  ADR か PR 本文に残すか確認してから、ファイルを削除する。未完了のときは止まって確認し、利用者が明示的に
  選んだ場合だけ削除する。確認が取り消されたとき、記録の書き込みに失敗したときは削除しない。archive には移さない（後から参照する記録は memory-layers ルールに
  従い PR・Issue・ADR に置く）
- **読み込みの安全性**: 名前が `<slug>.md` の規則に合わないファイルと symlink（`.claude/plans` 自体を含む）は
  読まない。読み込みに失敗したファイルはそれだけを飛ばし、hook は止まらない
- **対象ファイルの決め方**（`/task-state`・`/handoff`・`/order --from-plans`・`/grasp-check`）: slug を
  引数で指定する。省略時は、未完了のファイルが 1 つならそれ、複数なら利用者に選ばせ、0 なら案内する。
  `/order --to plans` は発注書ごとに新しいファイルを作り、`--from-plans` は Issue に出したファイルを削除し、
  `--from-issue` は新しいファイルを作る
- **設定**: `task-memory.yaml` の `plans_file` キーを廃止し、置き場所は `.claude/plans/` に固定する
  （`.gitignore` と照合するパスが固定のため、設定で変えても他が追従しない）
- **旧 Plans.md**: 読まない。存在すれば SessionStart で移行を促す 1 行の警告を出す。配布する `.gitignore`
  管理ブロックの `.claude/Plans.md` / `.claude/Plans.archive.md` は誤コミット防止のため残す。警告と
  エントリの削除は配布先がすべて移行してから Issue #521 で行う
- **scaffold**: 空の `.claude/plans/` を作り、`.claude/Plans.md` は作らない。雛形は
  `templates/project/plan.md` に改名し、スキルが新しいファイルを作るときに使う
- **codd**: 既定の scope から外す（git に入らないファイルなので、手元と CI で結果がずれる）。`plan` kind の
  語彙は残し、使う場合は `codd.local.yaml` で `.claude/plans/*.md` を足す。`/task-state` は frontmatter を
  付けない
- **パーサ**: `load-task-state.py` と `facets/scripts/handoff.py` の 2 つの実装を両方直す。1 つにまとめる
  のは本 ADR の対象外
