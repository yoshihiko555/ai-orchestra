# ADR-20260612-024: Gemini CLI を Anti-Gravity CLI（agy）に完全置き換える

- **ステータス**: accepted
- **日付**: 2026-06-12
- **決定者**: yoshihiko

## コンテキスト

Google の方針として Gemini CLI が廃止方向となり、個人ユーザーは後継の
Anti-Gravity CLI（コマンド名 `agy`）へ移行する流れになった。AI Orchestra は
リサーチ・大規模分析の委譲先として Gemini CLI を前提にしており（`gemini-suggestions`
パッケージ、`cli-tools.yaml` の `gemini:` セクション、`GEMINI.md` 指示書、
cocoindex の Gemini ターゲット等、約 84 ファイルが参照）、移行対応が必要になった。

実機検証（agy v1.0.7）で確認した事実:

- 非対話実行は `agy -p "..." --model <slug>` で完結し、Gemini CLI と異なり stdin 封じ不要
- **無効なモデル slug でも exit 0 でデフォルトモデルに黙ってフォールバックする**
- 設定ディレクトリは `~/.gemini/` を継続利用し、プロジェクトの `.gemini/settings.json` の
  `mcpServers` もグローバルとマージして認識する
- 指示書はプロジェクトルートの `AGENTS.md`（推奨）と `GEMINI.md`（互換）を読む

## 検討した選択肢

### 選択肢 A: 完全置き換え + フルリネーム（antigravity 系へ統一）

- メリット: 名前と実体が一致し保守性が高い。廃止予定 CLI への依存が残らない
- デメリット: 影響範囲が大きい。横展開先の旧設定（`.local.yaml` / `orchestra.json`）への互換対応が必要

### 選択肢 B: 併存（agy を追加し設定で切替）

- メリット: 段階的移行が可能
- デメリット: 廃止予定の Gemini CLI 系コードが保守負債として残る

## 決定

選択肢 A を採用する。後方互換は読み替えレイヤーで吸収する:

1. `cli-tools.yaml` に `antigravity:` セクションを新設（`model: gemini-3.1-pro-high`、
   `model_allowlist`）。旧 `gemini` 設定は 3 形態で読み替える
   （`gemini.enabled: false` の反映 / `agents.*.tool: gemini` の読み替え /
   `gemini.model` は Gemini CLI 固有値のため引き継がない。
   実装: `hook_common.normalize_cli_tools_config`）
2. 無効 slug の黙示フォールバック対策として、コマンド提案時に `model_allowlist` と
   突合し未掲載なら `[WARN]` を付与する
3. `packages/gemini-suggestions` → `packages/antigravity-suggestions` にリネームし、
   横展開先の `orchestra.json` は SessionStart 時に自動移行
   （`sync-orchestra.py` の `RENAMED_PACKAGES`）
4. `GEMINI.md` の生成・配布を廃止し、Antigravity 向け指示は `AGENTS.md` に統合
   （`context_files.fragments` による `codex.md` + `antigravity.md` のセクション合成）。
   横展開先の旧 `.gemini/GEMINI.md` は生成物マーカーを確認した上でのみ自動削除する
   （ユーザー手書きファイルは保持）
5. cocoindex の MCP プロビジョニングは `targets.antigravity` に改名しつつ、
   出力先は agy の仕様に合わせて `.gemini/settings.json` を維持する
6. `~/.gemini/` / `.gemini/settings.json` 等のランタイムパスとしての gemini 表記は
   agy 自身が継続利用するため残す（削除対象は CLI 呼び出しとしての gemini のみ）

## 影響

- リサーチ系ルーティング（`researcher` エージェント、`[Antigravity Suggestion]` hook、
  `/antigravity-system` スキル）はすべて `agy` を呼ぶ
- 横展開先プロジェクトは SessionStart の同期だけで自動移行される
  （旧 hook 登録の除去・旧パッケージ名の読み替え・旧 GEMINI.md の安全削除）
- audit の CLI 検知は `agy -p` を `tool: antigravity` として記録する
  （旧 `gemini -p` の検知はレガシーログ用に残置）
- 副次対応として、`codex exec` の stdin 封じ（`< /dev/null`）の徹底と
  `codex.model` の有効値（`gpt-5.5`）への追従を先行 PR で実施した
