# ADR-20260612-025: 失敗ログ記録基盤 fail-logs の新設と失敗検知ロジックの共通化

- **ステータス**: accepted
- **日付**: 2026-06-12
- **決定者**: yoshihiko

## コンテキスト

AI（Claude Code 等）は作業中にしばしば失敗するが、その痕跡はセッション終了とともに失われ、同じ失敗が繰り返される。「失敗を蓄積して次回以降に活かす」改善ループの第一歩として、失敗イベントを自動記録する基盤が必要になった。

既存パッケージの実態を調査した結果（実ログ 30 セッション）:

- `quality-gates` の `post-test-analysis.py` は全テスト実行で `quality_gate` イベントを emit し、audit がこれを消費して合格率 KPI を算出している
- しかし失敗キャッチは実質休眠中: `quality_gate` 55 件すべて `passed: true`、`cli_call` 33 件すべて失敗 0 件
- `quality_gate` の `passed` 判定は `exit_code == 0` のみに依存し、`pytest ... | tail -30` のようにパイプで終了コードがマスクされると失敗を `passed: true` と**誤記録する実例**を確認した（`is_test_failure` に出力ベース判定はあるが `passed` フィールドには使われていない）

## 検討した選択肢

### 選択肢 A: fail-logs が独自に失敗検知を実装（共通化なし）

- メリット: 最小工数。audit/quality-gates に一切触れない
- デメリット: 検知ロジックが将来 quality-gates と二重実装になり、パイプマスクバグが fail-logs 側でしか直らない

### 選択肢 B: quality_gate emit を廃止し fail-logs に一本化

- メリット: 責務の重複がゼロ
- デメリット: 合格率 KPI の分母（成功件数）が失われる。fail-logs は「失敗のみ記録」のため代替供給源にならず、audit の KPI/ダッシュボードの全面改修が必要で後方互換を破壊する

### 選択肢 C: quality_gate emit を存続し、失敗検知ロジックを core の共通ユーティリティに集約

- メリット: KPI の分母を保持しつつ、検知ロジックを一箇所に集約してパイプマスクバグを将来一括修正できる。後方互換を壊さない
- デメリット: 当面は捕捉レイヤーの重複が残る（ただし目的・スキーマが異なる）

## 決定

選択肢 C を採用する。今回は **fail-logs が共通ユーティリティを先行利用**し、quality-gates への適用は次フェーズに送る。

1. `packages/fail-logs` を **core 依存のみ**の独立パッケージとして新設する。PostToolUse hook（`capture-failures.py`）が失敗のみを `.claude/logs/fail-logs/failures.jsonl` に追記する（audit v1 互換スキーマ、所有者限定 `0600`、機密情報マスク済み）
2. 失敗検知ロジックを `packages/core/hooks/failure_detector.py`（純粋関数）に集約する。判定は 2 段構成:
   - ① `exit_code` が明示的に非ゼロ → 失敗
   - ② `exit_code` が 0/欠落でも test/lint コマンドで出力に失敗マーカー → 失敗（**パイプマスク対策**）
3. `quality-gates` の `quality_gate` emit は**存続**させる（合格率 KPI の分母・ダッシュボード・ゲート機能を保護）。今回は変更しない
4. fail-logs は **「失敗のみ記録」** を責務とする。成功の base-rate は引き続き `quality_gate` イベントが担う
5. audit / quality-gates は今回**一切変更しない**（後方互換最優先）

## 影響

- 責務境界: `audit`=オーケストレーションの compliance/observability、`quality-gates`=テストゲート + 合格率分母、`fail-logs`=失敗知識の蓄積（学習ループの入力）
- 当面、Bash 失敗の捕捉は fail-logs と quality-gates で重複しうるが、目的とスキーマが異なるため意図的に許容する
- `.claude/logs/` は gitignore 済みのためログはローカル蓄積（リポジトリを汚さない）

## 将来の移行パス（次フェーズ）

1. `quality-gates` の `post-test-analysis.py` を `failure_detector` に差し替え、`quality_gate` の `passed` 判定を 2 段判定に統一する（**パイプマスクバグを修正**）
2. 機密情報マスク（現在 audit-cli と fail-logs に重複実装）を core の共通ユーティリティへ切り出す
3. fail-logs の活用フェーズ: SessionStart での失敗サマリー注入、`.claude/rules/` への教訓昇格
4. これらは GitHub Issue として登録し追跡する（Plans.md「次フェーズ候補」参照）
