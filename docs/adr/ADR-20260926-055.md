# ADR-20260926-055: 機能フラグは所有パッケージの config に置き、quality-gates のフラグを audit-flags.json から分離する（ADR-016 の部分 supersede）

- **ステータス**: accepted
- **日付**: 2026-09-26
- **決定者**: yoshihiko
- **関連**: Issue #153、ADR-20260419-016（「共有設定として扱う」の一文のみ部分 supersede。責務分離の決定自体は有効のまま）、PR #54 / #150（`context_optimization` / `evaluation_set_check` の追加時に audit-flags.json へ同居を広げた経緯）、`.claude/rules/config-loading.md`（設定は所有パッケージの config に置く原則）
- **改訂**: 2026-09-26 — 読み替え shim を実装せず削除（PR #479 で一旦入れたものを追補 PR で除去。横展開先に旧キーの .local.json 上書きが存在しないため）
- **codd 注記**: codd グラフ上は ADR-20260419-016 への依存を `references` とする（codd の
  `supersedes` は全体置換の意味論のため。実際の変更範囲は「決定」節参照）

## コンテキスト

`audit` パッケージの `.claude/config/audit/audit-flags.json` に、`quality-gates` パッケージが
所有すべき 4 項目（`features.quality_gate` / `features.context_optimization` /
`features.evaluation_set_check` / `paths.state_dir`）が同居していた。

- `audit` のコードはこの 4 項目を一切読まない（`audit` 側の `quality_gate` はイベント記録の型名であり、
  設定フラグとしての `quality_gate.*` は判定・提案・ブロックを行う `quality-gates` 側の hook 群だけが
  参照する）
- ADR-20260419-016 は「quality gate の判定は quality-gates が担い、audit は記録と集計に限定する」と
  責務を分離しつつ、config の配置については「`audit-flags.json` の `quality_gate` セクションは
  `audit` と `quality-gates` の共有設定として扱う」と定めていた。この「共有設定」という位置づけが、
  後続の PR #54（`context_optimization` 追加）・PR #150（`evaluation_set_check` 追加）で
  「quality-gates 関連のフラグは audit-flags.json に足す」という慣習を作り、対象が広がった
- `.claude/rules/config-loading.md` の原則（設定は所有パッケージの `.claude/config/{package}/` に置く）
  と矛盾する状態になっていた
- Issue #153 でこの矛盾が指摘され、所有パッケージへの分離が提案された

## 検討した選択肢

### 選択肢 A: 現状維持で「共有設定」を正式化する

- メリット: 変更が最小。ドキュメントの追記だけで済む
- デメリット: `config-loading` の原則と矛盾したまま。`audit` を経由しないと `quality-gates` の設定が
  変えられない状態が固定化し、パッケージ単体でのインストール・アンインストールの妨げにもなる

### 選択肢 B: quality-gates 所有の config に分離し、`.local.json` は読み替えで互換を保つ

- メリット: 所有権が明確になり `config-loading` の原則に整合する。既存プロジェクトの
  `audit-flags.local.json` を書き換えなくても動作が変わらない
- デメリット: ローダーに新旧 2 ファイルを読む分岐が必要。deprecation 期間の管理コストが発生する

### 選択肢 C: 分離するが `.local.json` の読み替えは行わない（互換性を切る）

- メリット: ローダーの実装が単純
- デメリット: 既存プロジェクトの `audit-flags.local.json` にある上書き（例:
  `block_on_failed_test: false`）が sync 後に無言で失効する。後方互換性を優先する原則
  （`.claude/rules/coding-principles.md` 等）に反する

## 決定

**選択肢 C** を採用する（分離のみ。`.local.json` の読み替えは行わない）。横展開先に該当キーを
`audit-flags.local.json` で上書きしているプロジェクトが存在せず、配布 base は sync で自動的に
新版へ置き換わるため、後方互換の読み替えを持つ利点より保守コストが上回ると判断した。

- `packages/quality-gates/config/quality-gates.json` を新設し、`features.quality_gate` /
  `features.context_optimization` / `features.evaluation_set_check` / `paths.state_dir` を移す
- `packages/audit/config/audit-flags.json` を version 3 とし、上記 4 項目を削除する。残るのは
  `features.route_audit` / `features.kpi_scorecard` / `paths.logs_dir`
- `packages/quality-gates/hooks/quality_gate_config.py` の `load_quality_gates_config(project_dir)` が
  実効 config を返す。優先順位（後勝ち）は次のとおり:
  1. `quality-gates.json`（base）
  2. `quality-gates.local.json`（最優先）

  旧 `audit-flags.local.json` の該当キーは読まない

- `audit-bootstrap.py`（SessionStart）が `audit-flags(.local).json` に移動済みキーを見つけたら、
  移行案内を 1 行出力する
- ADR-20260419-016 のうち「`audit-flags.json` の `quality_gate` セクションは `audit` と
  `quality-gates` の共有設定として扱う」の一文のみを本 ADR で置き換える。「quality gate の判定は
  quality-gates が担い、audit は記録と集計に限定する」という責務分離の決定自体は引き続き有効であり、
  ADR-20260419-016 の ステータスは `accepted` のまま変更しない（全体 supersede ではないため）

## 影響

- 新規プロジェクトおよび今後の設定変更は `.claude/config/quality-gates/quality-gates.local.json` を
  使う。既存プロジェクトの `.claude/config/audit/audit-flags.local.json` に残る該当キーは読まれなく
  なるため、移行案内に従って `quality-gates.local.json` へ移す必要がある
- SessionStart 時に `audit-bootstrap.py` が移動済みキーの残存を検出すると、1 行の移行案内を
  stdout に出す（読み込み失敗時は fail-open で無視）
- 配布 base の `audit-flags.json` を手編集していて sync が更新をスキップしているプロジェクトでは、
  案内は値を `quality-gates.local.json` へ移すことだけを促す。案内を止めるには base を配布版に
  戻す（手編集をやめる）必要があるが、その手順は案内文には含めない（config-loading ルール上、
  base の手編集は想定外の運用のため）
- `packages/quality-gates/README.md` / `packages/audit/README.md` / `docs/reference/configuration.md`
  ほかの config-loading 関連ドキュメントを本決定に合わせて更新する
