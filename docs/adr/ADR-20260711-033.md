# ADR-20260711-033: meta-harness scenario runnerをSRTでOS隔離する

- **ステータス**: accepted
- **日付**: 2026-07-11
- **決定者**: yoshihiko

## コンテキスト

Phase 3の自動探索では、proposerが生成した候補ハーネスを`claude -p`で反復評価する。候補のhooksや
skillsは評価対象として意図的に実行されるため、Claude Codeの`--allowedTools`だけでは実HOME、
meta-harness store、sibling worktree、judge側の信頼設定への読み書きを防げない。候補が永続的に
`~/.codex/config.toml`等を汚染したり、資格情報をrun artifactへ出力したりすると、後続評価と
promotionの信頼境界が成立しない。

## 検討した選択肢

### 選択肢A: Claude Codeの権限制御だけを維持する

- メリット: 既存実装を変更せず、OAuth/keychain認証をそのまま利用できる。
- デメリット: OS上のファイル・ネットワーク境界にならず、候補hooksから実HOMEへ到達できる。

### 選択肢B: proposer用SRT基盤をscenario runnerにも適用する（採用）

- メリット: 実HOME・main repo・sibling worktreeをdenyし、評価worktreeだけを再許可できる。
  ネットワークも`api.anthropic.com`へ限定でき、既存canaryとversion pinを再利用できる。
- デメリット: SRTが使えない環境では評価がfail-closedになる。Claude CLI認証は環境変数に秘密を
  注入せず、OAuth/keychainが利用可能なホストに依存する。

### 選択肢C: コンテナ専用runnerを新設する

- メリット: より明示的なfilesystem/network境界を構成できる。
- デメリット: macOS開発環境のOAuth/keychain、worktree、Claude CLI配布形態との統合コストが高く、
  proposerで実証済みのSRT境界と二重の実装になる。

## 決定

選択肢Bを採用する。

- scenarioの`claude -p`全体を`srt --settings <json>`でラップする。
- SRT profileは実HOME、main repo、列挙済みworktreeをdenyし、対象の評価worktree、ephemeral HOME、
  per-run tmp、固定self-report instructionだけを再許可する。
- 子プロセス環境はallowlistから再構築し、`HOME`/`CLAUDE_CONFIG_DIR`をephemeral HOMEへ、
  `AI_ORCHESTRA_DIR`を評価worktreeへ固定する。`ANTHROPIC_API_KEY`等の親secretは継承しない。
- Claude CLIは通常モードのまま候補worktreeのproject/local settings・hooks・skillsを読み込むが、
  user settingsは読み込まない。認証はOAuth/keychain経路のみを利用する。
- SRT unavailable、version pin不一致、canary失敗は非隔離実行へ降格せずrun errorとする。
- run metadataにbackend、SRT version、settings hash、platform profile input hashを記録する。

## 影響

- `evaluate.isolation` configを追加する。
- SRTまたはClaude OAuth/keychainが利用できない環境ではscenario evaluationがfail-closedになる。
- 既存のproposer隔離APIと設定は維持し、scenario固有profileだけを追加する。
- candidate worktree内の挙動は評価対象として維持されるが、実HOME・store・他worktreeへの副作用は
  OS境界で遮断される。

## 追補

OAuth/keychainを同一process treeで利用する決定は、資格情報境界を再検証した
[ADR-20260711-034](./ADR-20260711-034.md)で置き換えた。SRTによるfilesystem/network隔離は維持するが、
外部credential brokerが実装されるまでscenario evaluationはfail-closedとする。
