# ADR-20260701-027: スキル自己改善ループの設計判断（二層構成・二軸評価・反映先の塩梅）

- **ステータス**: accepted
- **日付**: 2026-07-01
- **決定者**: yoshihiko
- **関連**: `req:skill-evolution`, `design:skill-evolution`（`docs/design/skill-evolution.md`）, ADR-20260624-026（facet 配布）, Issue #5

## コンテキスト

スキル実行の品質を自動で改善したい（`req:skill-evolution`）。実現にあたり、相互に関連する 3 つの
設計判断が必要になった。本 ADR はこれらを 1 件にまとめて記録する（判断ごとに ADR を分割しない）。

1. **ループ構成**: 毎回の学びを取りこぼさない軽さと、スキル自体を磨く深さは両立しにくい。
2. **評価基準**: 判定が甘いと「それらしく動いたが要件未達」を成功と誤認し、改善が誤収束する。
3. **反映先**: facet 製スキル（正本は `facets/`、`.agents/skills/` は `facet build` 生成物）と
   非 facet 製スキル（導入先独自）で、改善を書き戻すべき場所が異なる。

## 決定

### D1: 二層構成（オンライン軽量収集 ＋ オフライン反復改善）

- オンライン層: スキル発火ごとに二軸テレメトリを軽量収集し `lessons` に追記、発火前に注入する。**反復しない**。
- オフライン層: 明示的起動でのみ動く mizchi 型の停止条件付き反復ループ。

**理由**: 「軽さ」と「深さ」を層で分離すれば両立できる。オンライン層は既存 `context-sharing` の
inject/capture に載るため新規配線が最小（NF-04）。重い反復・judge をオフラインに隔離して
実行時オーバーヘッドを避ける（NF-01）。
**捨てた案**: 毎回オンラインで反復まで行う単層（実行のたびに重くコスト破綻）／オフライン反復のみ
（毎回の学びを取りこぼし、次回への即時還元ができない P-2）。

### D2: 二軸評価（自己申告＋機械計測）＋ `[critical]` 全達成ゲート

- 自己申告（不明瞭点・裁量補完・再試行）＋ 機械計測（`tool_uses`・`duration_ms`・チェックリスト達成率）。
- **成功判定は `[critical]` チェックリスト全達成を必須前提**。定量が高くても未達なら失敗扱い。
- 停止条件は mizchi 型（連続 2 回で「新規不明瞭点 0 / 精度 +3pt 以内 / ステップ ±10% / 時間 ±15%」全達成）。
  3 ガード（発散 3 回→構造再設計 / 過学習 holdout 15pt 超下落→停止 / コスト打ち切り / 最大反復上限）を併設。

**理由**: 定性・定量が互いの盲点（主観ブレ / 速いが誤り）を補う。`[critical]` ゲートで
「未達なのに成功」を防ぐ。明示的な停止条件・ガードで発散・過学習・コスト暴走を防ぐ（NF-02）。
**捨てた案**: 機械計測のみ（質的失敗を取りこぼす）／自己申告のみ（主観的で客観指標が無い）。

### D3: 改善反映先を出自で塩梅し、facet 自動昇格は当面しない

- 非 facet 製: lessons 蓄積＋注入を基本とし、SKILL.md へは diff 提示＋人間承認で反映。
- facet 製: 検証済みの学びを facet ソースへ昇格し、人間承認＋`facet build` 経由で配布
  （`.agents/skills/` 生成物は直接編集しない）。
- **facet 完全自動昇格（無人）はしない**。判別不能時は安全側で lessons 蓄積のみ（NF-05）。

**理由**: facet モデルの作法（生成物を直接編集しない／正本は facet ソース）を壊さない（ADR-026 と整合）。
導入先独自スキルを無断改変しない。人間承認ゲートで誤った改善の破壊的永続化を防ぐ（NF-03）。
**捨てた案**: 全部 lessons のみ（facet 製の改善が配布されない）／全部自動書き換え（生成物編集事故・無断改変）。

## 前提・未確定（実装着手前に確定が必要）

本 ADR は設計判断 D1〜D3 を `accepted` とするが、**実装可否を左右する 2 つの前提**が残る。
これらが崩れた場合、特に D1 のオンライン層の粒度は再検討となる（status は accepted のまま、
下記前提の確定をブロッカーとして扱う）。

- **発火検出 spike**（`design:skill-evolution` 3.8）: スキル発火を hook で捕捉できるか。失敗時は
  オンライン層の「発火前 lessons 注入」を起動時一括注入へ縮退するなど、マトリクスで縮退方針を持つ。
  D1 の二層構成自体（完了側の機械計測＋オフライン反復）は spike 結果に対して頑健。
- **自己申告収集メカニズム**（`design:skill-evolution` 3.5）: D2 の自己申告軸は、スキル完了時の
  標準化申告ブロックで取得する。欠落時は機械計測のみで記録し、`success` 判定（`[critical]` 達成）は
  維持されるため破綻しない。

## 影響

- `metrics/<skill>.jsonl`（機械収集）と `lessons/<skill>.md`（人間可読・注入対象）の 2 系統データを持つ。
- オンライン層は hook（発火前 inject / `SubagentStop`・`Stop` capture）、オフライン層は
  起動口（手動 / スケジュール / lessons 閾値）を持つ独立ランナーとして実装する。
- スキルアダプタ抽象（facet 製/非 facet 製の判別＋反映先解決）と人間承認ゲートを実装する。
- 詳細設計は `design:skill-evolution`、実装計画は `plan:skill-evolution`（`.claude/Plans.md`）を SSOT とする。
