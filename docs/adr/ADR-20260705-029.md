# ADR-20260705-029: Codex Review Gate による PR required status check の導入

- **ステータス**: accepted
- **日付**: 2026-07-05
- **決定者**: yoshihiko

## コンテキスト

ai-orchestra では Codex / CodeRabbit / 内部 `/review` のレビュー観点を揃えたが、PR 上で Codex レビューが
実行済みかどうか、未解決指摘が残っているかどうかは GitHub の必須チェックとして可視化されていなかった。
そのため、Codex レビューが未実行または未解決のままマージされる余地があった。

必要な状態は次の 2 点である。

1. PR の head commit に `codex/review-gate` status を表示する。
2. Codex の未解決指摘がある場合、GitHub Ruleset / Branch protection の required status check で
   マージを止められるようにする。

## 検討した選択肢

### 選択肢 A: `JoeyTeng/codex-review-gate-action` を導入する

- メリット: `@codex review` の制御コメント投稿、Codex 結果の監視、`codex/review-gate` commit status 更新を
  既存 Action に委ねられる。required status check と組み合わせやすい
- デメリット: GitHub 公式認定 Action ではないため、サードパーティ Action として権限・供給網リスクを管理する必要がある

### 選択肢 B: 独自 Action を実装する

- メリット: 権限・判定ロジック・リリース管理を完全に制御できる
- デメリット: Codex レビュー完了判定、未解決 thread 判定、イベント再試行を自前で保守する必要があり、導入コストが高い

### 選択肢 C: Codex automatic reviews のみを使う

- メリット: 追加 workflow が不要
- デメリット: GitHub の required status check として扱える `codex/review-gate` がなく、未解決指摘でマージを止める
  明確な信号にならない

## 決定

選択肢 A を採用する。`.github/workflows/codex-review-gate.yml` を追加し、`codex/review-gate` commit status を
更新する GitHub Actions workflow として運用する。

運用上の前提は次の通り。

- Codex settings では対象リポジトリの Code review を ON、Automatic reviews を OFF にする。
- workflow は `pull_request_target` を使うが、`actions/checkout` は行わず、PR ブランチ由来のコードを実行しない。
- 最初に workflow を default branch へマージし、テスト PR で `codex/review-gate` が success になることを確認してから
  GitHub Ruleset / Branch protection の required status check に追加する。
- required status check の source は GitHub Actions を選択する。
- サードパーティ Action の供給網リスクが許容できない運用では、タグ参照から full-length commit SHA pinning へ切り替える。

## 影響

- PR 作成・更新時に Codex Review Gate workflow が起動し、`codex/review-gate` status が表示される。
- Ruleset / Branch protection で `codex/review-gate` を必須化すると、Codex の未解決指摘がある PR は
  マージできなくなる。
- Dependabot PR は初期導入では対象外とし、通常 PR で安定確認後に必要なら除外条件を外して適用範囲を広げる。
- workflow 削除や無効化を行う場合は、先に Ruleset / Branch protection から `codex/review-gate` の required 指定を外す。
