# ADR-20260928-058: Plans.archive.md と SessionStart の自動アーカイブを廃止する（ADR-056 の部分 supersede）

- **ステータス**: accepted
- **日付**: 2026-09-28
- **決定者**: yoshihiko
- **関連**: ADR-20260926-056（§決定 1 の「Plans.md の Project を Issue に出したら Plans.archive.md に移す」の
  一文のみ部分 supersede。発注書を 1 エンジン 1 か所に置く決定自体は有効のまま）、ADR-20260927-057（記憶の層の
  分担。残す記録の置き場所は memory-layers ルールに従う。§決定 3 の根拠「Plans.md の Decisions は全 Project の
  完了時にアーカイブされるため」は本 ADR により「Plans.md の Decisions は worktree と一緒に消えるため」に
  置き換わる。ADR に残すという決定自体は有効のまま）、CHANGELOG の「Plans.md の管理指針を worktree
  ローカル運用に明確化」
- **codd 注記**: codd グラフ上は ADR-20260926-056 への依存を `references` とする（codd の `supersedes` は
  全体置換の意味論のため。実際の変更範囲は「決定」節参照）

## コンテキスト

`packages/core/hooks/load-task-state.py` は SessionStart のたびに、全 Phase が完了した Project
（タスクがすべて `cc:done` かつ AC がすべて `[x]`）を `Plans.md` から取り除き、同じディレクトリの
`Plans.archive.md` に日付付きで追記していた。全 Project が完了したときは Decisions / Notes も移していた。
`/order --from-plans` も、Issue に引き渡した Project を同じ形で `Plans.archive.md` に移していた。

Plans.md と Plans.archive.md を worktree ごとのローカルファイル（gitignore）にしてから、この処理は
次の 2 点で役目を果たさなくなった。

- **走る機会がない**: Project を完了させるのはその worktree の最後のセッションで、アーカイブは「次の」
  SessionStart で走る。PR をマージしたら worktree を `git gtr rm` / `git gtr clean --merged` で消すため、
  次の SessionStart が来ない
- **書いても残らない**: 書き先は `.worktrees/<name>/.claude/Plans.archive.md` で、worktree と一緒に消える。
  root の `.claude/Plans.archive.md` は worktree ローカル運用に移って以降（2026-03-22 が最終更新）、
  何も追記されていない

一方、タスクが終わった後も参照する記録の置き場所は、ADR-20260926-056 と ADR-20260927-057 で
PR 本文・Issue・ADR に決まっている。Plans.archive.md に長期の記録を求める理由はもう無い。

## 検討した選択肢

### 選択肢 A: 処理は残し、Plans.archive.md を worktree 内の一時ファイルと明記する

- メリット: ルールの記述を直すだけで済み、挙動は変わらない
- デメリット: 実質動かない処理と、それを検証するテスト・評価観点を持ち続ける

### 選択肢 B: worktree を消すときに root の Plans.archive.md へ集める

- メリット: 完了履歴が root に残る
- デメリット: `gtr` の preRemove フックに依存し、`git worktree remove` を直接使う場合や gtr を使わない
  配布先では動かない。残したい記録は PR・Issue・ADR と重複する

### 選択肢 C: SessionEnd でもアーカイブする

- メリット: 最後のセッションで完了した Project がその場で移る
- デメリット: 書き先が worktree と一緒に消える問題は残る。A か B と組み合わせる必要がある

### 選択肢 D: Plans.archive.md を扱う処理をすべて廃止する

- メリット: 実質動かない処理・テスト・評価観点・ルール記述をまとめて消せる。SessionStart の hook は
  Plans.md を読むだけになる
- デメリット: 完了した Project が Plans.md に残り、Goal の注入も続く。root で Plans.md を使い回す場合は
  片付けが手動になる

## 決定

**選択肢 D** を採用する。後方互換（自動除去を残す・設定で切り替える等）は残さない。

- `load-task-state.py` は Plans.md を書き換えない。完了 Project の検出・Plans.md からの除去・
  Plans.archive.md への追記・Decisions / Notes の移動をすべてやめる。サマリーの注入はこれまでどおり行う
- `/order --from-plans` は、Issue を作ったあと Project を Plans.md から取り除くだけにする。発注書の内容は
  Issue 本文に残るので、二重に状態を持たない原則（ADR-20260926-056 §決定 1）は保たれる
- Phase の完了の定義（タスクがすべて `cc:done` かつ AC がすべて `[x]`）は、`/goal` のループ判定と
  `/release-readiness` の確認に使う定義として残す
- タスクが終わった後も参照する記録は、PR 本文・Issue・ADR に書く（memory-layers ルール）
- 配布する `.gitignore` 管理ブロックの `.claude/Plans.archive.md` エントリは残す。管理ブロックは sync の
  たびに置き換わるので、エントリを消すと既存プロジェクトに残ったファイルが未追跡になり、誤ってコミット
  されうるため
- `packages/core/hooks/ac_parser.py` の公開関数 `ac_section_ranges` / `phase_has_unchecked_ac`（と内部の
  `_find_ac_section_end`）は、完了 Project の検出でしか使っていなかったため削除する。AC 見出しの定義と
  チェックボックス行の分類（`AC_SECTION_HEADING` / `classify_checkbox_line`）はサマリーで AC 行を除外する
  ために残す

## 影響

- 完了した Project は Plans.md に残り、SessionStart の注入にも Goal が載り続ける。worktree 運用
  （1 worktree = 1 タスク）では worktree ごと消えるので問題にならない。root で使い回す場合は、不要になった
  Project を手動で消す
- 既存の Plans.archive.md ファイルは削除しない。不要なら利用者が手動で消す
- `docs/evaluation/core.md` の自動アーカイブの観点（EV-02 / 03 / 18 / 21 / 22 / 23 / 25 / 44）と
  `docs/evaluation/skills/order.md` の EV-10 の該当部分を改める。削除した ID は欠番として残す
- 挙動が変わるため、CHANGELOG には `**BREAKING**` として記載する
