# ADR-20260814-050: skill target の品質分解能を gate/graded 分離（独立 graded リスト + penalty 非採点）で実現する

- **ステータス**: accepted
- **日付**: 2026-08-14
- **決定者**: yoshihiko
- **関連**: Issue #364、ADR-20260814-049（決定 4 の前提条件と決定 5 の「必要性再浮上」条項）、
  ADR-20260814-048（gate/graded 機構の原設計 — routing-config 用途は撤回済み、本 ADR で
  skill target に再設計）、ledger 分析 2026-08-14（適格 run 品質分散の由来確認）

## コンテキスト

ADR-049 決定 4 の前提条件として実施した ledger 分析（497 run、$0）で以下が確定した:

- **適格（verdict=pass）run 間の品質差は自己申告 penalty のみ由来**。構造的必然
  （pass ⟺ 全 critical 通過 ⟺ critical_pass_rate=1.0 → quality = 70 + max(0, 30−5×penalty)）
  であり、実データでも 320/320 全件で例外なし
- penalty の主因は discretion_fills の自己申告で、**同一条件の反復 group の 40% で値が
  変動する非決定性**を持つ（reward hacking 脅威 A5 の面 + ノイズ源）
- 既存の rubric_judge（非 critical checks）は **judge への成果物受け渡しが機能しておらず
  品質と無相関**（正しく作業した run が「参照ファイルなし」で不合格になる）。graded の
  種として直接使えない。judge 入力経路の修理は本スコープの loop 運転（rubric 不使用）に
  影響しないため、既知事項としてここに記録するに留める（Issue は起票しない — 決定者指示）
- issue-fix / issue-create の高 error 率（累積 62〜64%）は較正前（8/9 以前: 96〜98%）の
  遺産で、**較正後（8/10 以降）は 8%**。loop 経済性の問題はない

よって ADR-049 決定 5 が予告した「gate/graded の必要性が skill target で再浮上した場合」に
該当し、本 ADR で skill target 向けに再設計する。ADR-048 の原設計（graded-only 分母・
独立エンドステート採点・holdout 異質バグ）を土台に、分析結果（penalty の A5/ノイズ性）を
反映して penalty の扱いを変更する。

## 決定

1. **graded は独立した top-level リストとして実装する**: シナリオ YAML に `graded:`
   配列（check_item と同スキーマ、機械 oracle のみ）を新設する。`critical:` は従来どおり
   gate 専用（fail で verdict=fail）で、**verdict 判定機構は無改修**。事前検証で確認した
   とおり、この分離設計なら regression の hard gate 合成（EV-54/75）も構造的に保たれる
2. **graded 宣言シナリオの quality = graded_pass_rate × 100 とし、penalty は非採点化する**
   （self_report は記録・監査用として保持）。自己申告を loop の品質信号から構造的に除去し
   A5（自己採点 gaming）と penalty ノイズ（±5pt 刻みの非決定変動）を封じる。graded 未宣言の
   既存シナリオは従来式（70/30 + penalty）のままで後方互換
3. **graded の oracle は機械的検証（command_exit / artifact_exists / json_schema）のみ**。
   rubric_judge は使わない（上記の入力経路不全のため。修理後の組み込みは将来の別判断）
4. **issue-fix suite を転換する**: train（fix-greet-none-bug）と holdout
   （fix-formal-greeting-feature-holdout）の**両方**を同一方針で転換する（片方だけ転換
   すると `_retire_if_overfit` の 15pt 劣化判定が異種スケール比較になるため）。分類原則:
   gate = 実行成立性（成果物の存在・リポジトリ非破壊・実行完了）、graded = 出来栄え
   （修正内容の複合 assert・decision 内容一致・call-log 一致などの独立エンドステート検証）
5. **regression strict mode**: routing-config 候補等の regression 評価文脈では、graded の
   fail も suite fail として扱う（converted criticals が gate から抜けることで回帰ゲートが
   弱まる穴を塞ぐ。撤回された ADR-048 の EV-75 条項の実質復活）。**この点は決定者への
   再確認なしに実装裁量で確定した**（承認済み原則〈EV-54/75 の hard gate 維持〉からの
   演繹であり、PR レビューが確認ゲート）。実装は verdict 計算への文脈フラグ貫通を第一候補
   とし、貫通が複雑な場合は「regression 側で result の graded 結果を読み suite verdict
   合成時に fail 扱いする」後段合成方式に切り替えてよい
6. **実効刻みは `100 / (graded 項目数 × non-holdout シナリオ数)`**（penalty 非採点化に
   伴う新式。ADR-048 の 70 ベース式は失効）。issue-fix own suite は train 1 本のため
   graded 3 項目で **33.3pt 刻み**。convergence band（3pt）・progress epsilon（0.5pt）に
   対して十分粗く、誤収束は起きず、実改善（graded 1 項目の flip）は必ず検出される。
   刻みの細分化はシナリオ・graded 項目の追加で後から可能であり ADR は不要
7. **suite 内の non-holdout シナリオは graded 宣言を揃える**（宣言/未宣言の混在は
   quality_mean が異種スケールの平均になるため禁止。schema またはバリデーションで
   強制できない場合は評価セット + ドキュメントの制約とする）
8. **運用順序**: 本 ADR の実装 PR マージ後に skill:issue-fix の noop baseline
   （**空 overlay**。skill target は config_patch 禁止のため）を bootstrap する
   （evaluator_hash / facet closure hash の stale 化を避けるため、evaluator・facet に
   触れる全マージの後に 1 回だけ）。loop 運転は skill target では候補評価失敗 1 件で
   loop 全体が停止する（routing-config のような cooldown 継続なし）ため、`--resume`
   前提の監視運用とする

## 影響

- 変更対象: `schemas/scenario.schema.json` / `schemas/result.schema.json`（+必要なら
  ledger event schema）、`lib/evaluator.py`（graded 実行・quality 算出・regression strict）、
  `lib/meta_harness_common.py`（quality_score の graded 対応）、
  `scenarios/skill/issue-fix/*.yaml` 2 本、対応テスト、
  `docs/evaluation/meta-harness.md`（EV-103 の後継となる新 EV: graded 意味論・penalty
  非採点・regression strict・suite 内宣言統一）+ checks sidecar、
  `docs/design/meta-harness-detailed.md` §3-2 の追従
- evaluator_hash / suite_hash が変わるため、既存の評価・frontier は stale 化する
  （skill:issue-fix は未 bootstrap のため実害なし。routing-config は検証専用 target の
  ため追わない）
- #364 の残り工程: 本実装 PR → bootstrap（空 overlay、train+holdout 同一 evaluation）→
  loop 再運転（budget_usd: 40 目安 + 人間監視 + --resume）→ 完了判定（品質差 frontier
  または実体を伴う停止。空虚な converged は不可 — ADR-049 決定 4/6）
