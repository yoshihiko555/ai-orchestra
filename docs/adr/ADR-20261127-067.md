# ADR-20261127-067: API キーによる用途非依存の LLM 呼び出し基盤

- **ステータス**: accepted
- **日付**: 2026-11-27
- **範囲**: T2。合意済みの API 共通基盤を実装する。ADR-066 の T1 と Codex の委譲手順は維持する。

## コンテキスト

調査は Claude 自身で完結できるが、検索のグラウンディング、添付、長い文脈を使う場合に
各社の API を API キーで一回呼ぶ共通入口が必要となった。
API プロファイルを追加するときに Python コードを変更せず、SDK がなくても基本機能を動かす。

## 検討した選択肢

- 公式 SDK を optional extra に置く。各社の認証・タイムアウト・リクエスト形式を SDK に任せられる。
- HTTP を直接実装する。基本依存は増えないが、API の違いを自前で維持する必要がある。
- 呼び出し全体を researcher に埋め込む。小さく始められるが、他の用途で再利用できない。

## 決定

- 公式 SDK の anthropic / openai / google-genai を `orchex[llm]` へ置き、基本依存は pyyaml のままとする。
- 認証・プロファイル・利用可否は core の標準ライブラリだけで解決し、hook と CLI が共有する。
- SDK を使うアダプタは `scripts/lib/llm/` に置き、用途やエージェント名を持たせない。SDK は実行時に import する。
- プロバイダのモデル、プロファイルのモデル・機能・上限は base/local 設定から読む。
  モデルは profile → provider の順に選ぶ。allowlist 外は警告する。
- 利用可否は無効 → キー不足 → SDK 不足の順に一つの理由を選ぶ。routing は direct に戻り、CLI は対応する終了コードを返す。
- キーは環境変数を優先し、未設定なら ~/.config/orchex/credentials を読む。保存は INI、0700 / 0600、原子的置換とする。
  キーを引数、設定、routing、ログ、例外表示へ含めない。SDK の詳細例外も表示しない。
- API を一回呼び、SDK の自動再試行とクライアント側の function calling を使わない。
- 既定のプロファイルは Gemini research だけ。researcher は Claude 自身が探索し、必要時だけ API を補助として使う。

## モデルと API 形式の参照

2026-11-27 の公式資料を確認し、既定モデルを anthropic: `claude-sonnet-5-5`、openai: `gpt-6.2-sol`、gemini: `gemini-4-neon` とした。
モデルは設定値として上書きでき、テストでは具体的な既定モデル名を固定しない。

- [Anthropic models](https://platform.claude.com/docs/en/models/overview)
- [Anthropic SDK の web search 例](https://github.com/anthropics/anthropic-sdk-python/blob/main/examples/web_search.py)（web_search_20250305）
- [OpenAI models](https://developers.openai.com/api/docs/models)
- [OpenAI web search](https://developers.openai.com/api/docs/guides/tools-web-search)
- [Gemini models](https://aistudio.google.com/docs/models)
- [Google Gen AI SDK](https://googleapis.github.io/python-genai/)（dict 入力、GenerateContent、クライアントの close）

## 影響

`orchex auth set/status` と `orchex llm ask --profile` を追加する。CLI と hook の routing で同じ設定・利用可否を使う。
Anthropic / OpenAI のプロファイルは local へ追加できるが、既定ではエージェントに結び付けない。
第2段階のエージェントループ、function calling の差の吸収、LiteLLM の採用判断は対象外とする。
