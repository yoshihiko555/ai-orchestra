# ADR-20261127-069: 読み取りエージェントのループ・根拠確認と API 委譲の共通運用

- **ステータス**: accepted
- **日付**: 2026-11-27
- **範囲**: 第 2 段階のループ・根拠確認・共通 rule・比較評価。ADR-067/068 の本文と認証・プロファイル・道具の 1 往復の契約は維持する。

## コンテキスト

一回の API 呼び出しだけではリポジトリを探索できない。道具付きの往復には上限と部分結果が必要で、
長時間実行を呼ぶ側にも、終了ファイルの待機と根拠の裏取りが必要になる。
用途ごとのサブエージェントに同じ運用を複製せず、共通の rule として配布する。
API を利用する探索を採用する判断には、正解が決まった問題で Claude 自身の探索と比較する手段が要る。

## 検討した選択肢

- エージェントごとに待機・partial・根拠確認の手順を書く。
  個別の説明は短くできるが、終了コードや期限の扱いが分かれる。
- agent-routing の共通 rule として生成する。
  tool と api_profile の設定の所有者と配布先が揃い、すべての API 利用サブエージェントへ同じ運用を適用できる。
- 評価を配布 CLI に組み込む。
  利用者にも届くが、このリポジトリ固有の正解セットと実験の道具まで配布してしまう。

## 決定

- `run_agent_loop` は既存の道具付き 1 往復を繰り返し、呼び出し ID 付きで道具の結果を返す。
  往復・累計トークン・探索時間の上限では道具なしのまとめを一回行い、partial と停止理由を返す。
  rate_limited だけを指定回数再試行し、quota_exhausted / auth_error は即時停止する。
- `ReadLedger` が実際に返した行範囲を持つ。`parse_final_answer` → `verify_citations` →
  `RepoReadTools.check_citation` で、実在・行範囲・読取範囲を確認する。意味的な正しさは保証しない。
- `llm agent --output` は空の出力先を占有し、progress.json、result.json、最後に exit を書く。
  ファイルの受け渡しと既存の終了コードを変更しない。
- `api-delegation` を facets の instruction と composition から生成し、agent-routing の manifest に登録する。
  ask / agent の使い分け、hook の解決値、partial の冒頭報告、待機、終了コード別の対応、Read による裏取りを共通化する。
  待機期限は探索上限 + 一要求の timeout の 2 倍とする。既定では 900 + 240 = 1140 秒。
- 評価は配布しない `tests/experiments/repo_understanding_eval.py` に置く。
  20 問を 4 種類各 5 問とし、正解要点と指定行内の文字列で根拠のずれを検出する。
  基準は Read / Grep / Glob だけの `claude -p`、対象は同じ checkout の `llm agent`。
  Claude に要点との照合で採点させ、人が抜き取り確認できる一覧も出す。
- 全体・種類別の正答率、未確認根拠の割合、トークン、探索時間を集計する。
  採用条件は基準の正答率の 9 割以上かつ未確認根拠 1 割以下。整数比で境界を判定し、根拠ゼロは不採用とする。

## 影響

ルーティング設定や認証の解決は変えない。既存 rule の表と説明は正本から追従し、生成物を手編集しない。
Codex 向けの rule は生成せず、cli-language を使う skill の表だけを再生成する。
基準方式の読取記録は成功した Read の offset / limit から作り、Grep は含めない近似である。
評価用正解の参照防止と Read の表示範囲には比較上の限界があり、手順と報告に残す。
手順は [比較評価の README](../evaluation/repo-understanding/README.md) に置く。
実 API による評価はこのタスクでは行わず、人がキーを設定し実行を了承した後だけ `--confirm-real-api` で実行する。

## 検証方法

API 不要の check と `tests/unit/test_repo_understanding_eval.py` で、問題形式・根拠のずれ、
runner への引数、出力先、採点結果の伝達、集計と採用境界を確認する。
ループ・エラー・道具・CLI の既存テストを維持し、Python 3.12 の pytest、ruff、facet build で検証する。
