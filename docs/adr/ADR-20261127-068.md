# ADR-20261127-068: any-llm による道具の1往復とAPIエラー分類・再試行

- **ステータス**: accepted
- **日付**: 2026-11-27
- **範囲**: 第2段階の道具呼び出し基盤。ADR-067の認証・設定・検索・添付を維持し、
  一回の呼び出し方針をレート制限の再試行と道具付きの1往復について拡張する。
  ADR-067自体は変更しない。

## 比較方法

Python 3.12.12の隔離venvで、any-llm-sdk 1.55.0とlitellm 1.106.2を比較した。
`tests/experiments/llm_library_comparison.py any|litellm` を各venvのPythonで実行する。
共通のHTTP応答fixtureを実ライブラリへ渡し、同名の2呼び出しへ逆順で結果を返す。
各社で2回目の応答、ID、Geminiの署名、quota/rate/auth例外の機械向け情報を観測する。
一時HOMEとダミーキーを使い、HTTPのsendを差し替え、socket接続を禁止する。
実APIは呼ばない。

LiteLLMの基本extraだけではcompletion時に `mcp` のImportErrorとなったため、
実行可能な `litellm[mcp]==1.106.2` を比較対象とした。
GeminiのfixtureにはLiteLLMが必須とする `usageMetadata` も含める。

## 比較結果

| 基準 | any-llm-sdk[gemini] 1.55.0 | litellm[mcp] 1.106.2 |
|------|---------------------------|---------------------|
| (1) 3社の道具呼び出しと結果の往復 | 3社とも2要求で成功。元のID、引数、結果の対応、Geminiの署名を保持 | 3社で2回目の回答まで到達。Anthropic/OpenAIの対応は成功。Geminiは元のIDを置換し、再送するfunctionCallのidが欠落したためID保持の検査は失敗 |
| (2) エラー分類情報 | `unified_exceptions=False` で各社のSDK例外を保持。OpenAIのcode、Anthropicのstatus/type/error_code、Geminiのcode/status/detailsを分類に利用可能 | 統一例外は429のcodeを `"429"` に置換。OpenAIの元コード、GeminiのQuotaFailureやErrorInfoは例外連鎖内のSDK例外・HTTP応答から取得可能。統一例外のresponseはJSONを保持しないケースがある |
| (3) 依存と固定 | 現行の3公式SDKを変更せず15パッケージ追加。`==1.55.0` とSHA-256で固定可能 | 47パッケージ追加とOpenAI 3.60.0→2.54.0の置換（install対象48）。`==1.106.2` とSHA-256で固定可能 |
| (4) Python 3.12 | requires-python >=3.11。3.12.12で上記実験を実行 | requires-python >=3.10,<3.15。3.12.12で上記実験を実行 |

依存数は導入前の本worktreeの3公式SDK導入済みvenvに対する
`uv pip install --dry-run --python .venv/bin/python '<候補extra>==<版>'` の差分であり、
テスト支援依存を含む隔離venvの全パッケージ数ではない。
計画時の16/41という事前調査値ではなく、実装時の15/48という解決結果を使用した。

## 公開版とハッシュ

[LiteLLMの3月の公式報告](https://docs.litellm.ai/blog/security-update-march-2026) は
1.82.7/1.82.8の侵害を説明している。
[10月21日の公式報告](https://docs.litellm.ai/blog/security-incident-oct-21-2026) は
1.107.0を侵害された版とし、1.106.2への切り戻しを案内している。
この公式の案内に基づき1.106.2を候補とした。ハッシュの一致は公開物の同一性を示し、
パッケージ全体の安全性を保証するものではない。

PyPI JSONのハッシュとダウンロードしたwheelのSHA-256を照合した。

|------|---------------|---------|
| any-llm-sdk 1.55.0 | any_llm_sdk-1.55.0-py3-none-any.whl（428,075 bytes） | `547a16520c1d44216bf176001c80ad848c474f1bde9dc076acd693973f3ea2a1` |
| litellm 1.106.2 | litellm-1.106.2-cp310-abi3-macosx_11_0_arm64.whl（35,263,059 bytes） | `cc778d01ed65a8dd57d5211d581ec237e06df239a09c3d573ace33e0feea76c9` |

出典: [any-llm-sdk 1.55.0の配布情報](https://pypi.org/pypi/any-llm-sdk/1.55.0/json)、
[LiteLLM 1.106.2の配布情報](https://pypi.org/pypi/litellm/1.106.2/json)。
採用したany-llmのハッシュは `uv.lock` にも保存する。

## 決定

- any-llm-sdk[gemini] 1.55.0を `llm` extraへ厳密固定で追加する。
  3社の往復・状態保持と分類情報を確認でき、依存が小さく、現行の公式SDKと併用できる。
  LiteLLMのID保持に追加対応を行う選択肢でも依存数は変わらないため、選定規則からany-llmを選ぶ。
- 基本依存はpyyamlのみとする。SDK・any-llmは呼び出し時にimportする。
- 既存askは各公式SDKを使用し、検索・添付の変換を保持する。
  道具付きの新入口だけはany-llmのchat形式へ変換する。公開するのは用途に依存しない
  `ToolSpec`、`ToolCall`、`ToolResult`、会話・要求・応答の型と `call_tool_turn` とする。
- 応答の正規化済みメッセージをプロバイダ名とJSONの組で保持し、次の要求へ戻す。
  これによりGeminiの署名などを失わず、SDKの型やクライアントを利用側へ公開しない。
  結果は呼び出しIDで対応付け、異なるプロバイダへの状態の流用を拒否する。
- SDKとライブラリの自動再試行・道具の自動実行を無効にする。ループと道具は実装しない。
  OpenAIでは保存を無効にする。クライアントは例外時を含めてcloseする。
- `unified_exceptions=False` を指定し、ライブラリのメッセージ照合による例外変換を避ける。
  ピンした版では将来の統一例外への移行を促すDeprecationWarningが出るが、
  現時点では元のSDK情報を保持する方式を使用する。

## エラーと再試行

分類の所有者は `errors.py` とする。既存askと道具APIが同じ分類関数を使い、
`types.py` の固定メッセージを返す。timeout/api_errorの既存分類も保持する。

- OpenAI: 429かつ `insufficient_quota` はquota、他の429はrate、401/403はauth。
- Anthropic: 402、`billing_error`、支出上限の機械向けコードはquota。
  その他の429はrate、401/403はauth。支出上限を429より先に判定する。
- Gemini: 429の `RESOURCE_EXHAUSTED` で `QuotaFailure` のquotaIdに `PerDay` があればquota。
  その他の429はrate。401/403および400の `ErrorInfo.reason=API_KEY_INVALID` はauth。
  PerDayの判断は今回の設計上の規則であり、あらゆる利用枠不足の応答を網羅したとの主張ではない。
  詳細がない場合に本文の文言から推測しない。
- quota/rate/authのCLI終了コードは9/10/11。既存0、2〜8は変更しない。
- 再試行関数は初回を含む回数と待ち時間、倍率を受け取り、rateだけを再試行する。
  CLIは合計3回、2秒・4秒待つ。quota/authとその他の失敗は直ちに返し、
  回数切れでは最後のrateエラーを返す。道具API自身には組み込まない。

例外・本文・ヘッダを分類のために文字列化しない。SDK・HTTP・any-llmの診断ログは
呼び出し中だけ固定文字列へ置換し、書式化・例外整形の前に本文・引数を取り除く。
呼び出し後には元のログ設定を復元し、通常のアプリケーション診断を保持する。

## 確認

`tests/unit/test_llm_tool_turn.py` は共通入口から実SDKとHTTPモックを経由した往復、
署名・ID・引数・結果の保持と1要求での停止を検証する。
`test_llm_errors.py` はstr/reprを拒否する例外を使い、本文に依存しない分類を検証する。
`test_llm_cli.py` はCLI終了コード、分類別メッセージ、秘匿、429後の成功を観測する。
`test_llm_retry.py` は待機列、最終例外、rateからauthへ変化した後の停止を観測する。
`test_llm_sdk_logging.py` は後から作られたロガーと例外終了後の復元も検証する。
実API・実キーは使用しない。全体のDockerテストはmanagerがsandbox外で実行する。
