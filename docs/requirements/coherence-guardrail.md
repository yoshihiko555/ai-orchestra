# 要件: ドキュメント整合性ガードレール

**AI Orchestra および導入先プロジェクトが生成するドキュメント群の整合性（coherence）を、
配布可能なパッケージとして担保する。**

## 背景

設計書・ADR・計画・ルール・指示書は相互に依存するが、依存関係が暗黙的なため、
上流を変更しても下流が追従されず不整合が蓄積する。CODD（Coherence-Driven Development）の
思想に倣い、依存をドキュメント自身が宣言し、機械的に検証できる状態を要件とする。

## 機能要件

- **FR-1**: 各ドキュメントが依存関係をフロントマター（`codd:` ブロック）で宣言できること。
- **FR-2**: 依存グラフを走査・構築できること（`scan`）。
- **FR-3**: 整合性の不整合（リンク切れ・重複・循環・未定義語彙・孤立・ドリフト・欠落）を
  検出できること（`validate`）。
- **FR-4**: 整合性レイヤーを配布レール（packages / presets / facet build）に載せ、
  導入先プロジェクトへ展開できること。

## 非機能要件

- **NFR-1**: 既存の CLI・設定キーの後方互換を壊さないこと。
- **NFR-2**: 依存宣言の正本は単一（ドキュメント内フロントマター）であること（二重管理の禁止）。
- **NFR-3**: error 検出時は非ゼロ終了し、CI/フックへ組み込み可能であること。

## 受け入れ基準

- `scan` がスコープ内ドキュメントから依存グラフを構築し JSONL に出力する。
- `validate` がリンク切れ・重複・循環・未定義語彙を error として検出する。
- AI Orchestra 自身のドキュメントで `validate` が error 0 で通る（ドッグフード）。
