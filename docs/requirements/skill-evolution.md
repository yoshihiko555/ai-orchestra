# Skill Evolution（スキル自己改善ループ）要件定義

**作成日**: 2026-07-01
**ステータス**: draft
**起点**: Issue #5
**関連**: `design:skill-evolution`（`docs/design/skill-evolution.md`）

## 1. 背景

AI Orchestra のスキル（`.claude/skills/` / facet 由来の `.agents/skills/`）は一度書かれると
固定化され、実行のたびに品質がばらついても自動で改善されない。スキルの良し悪しは「実行ログ」
に現れるが、その情報は捨てられており、次回実行に活かされない。

Issue #5 は当初「成果物のセルフレビュー自動化（A）」と「スキル自体の自己改善ループ（B）」の
2 つを含んでいた。A は既存 `skill-review-policy`（スキル内レビューフェーズ）と大部分が重複する
ため、本要件では **A を最小拡張に縮小し、B を主役**に据える。

## 2. 課題

| #   | 課題                                                                         |
| --- | ---------------------------------------------------------------------------- |
| P-1 | スキル実行の品質（不明瞭点・裁量補完・再試行・所要・ツール数）が計測されない |
| P-2 | 過去実行の学び（lessons）が次回実行へ還元されない                            |
| P-3 | スキルの改善が人手の場当たりで、停止条件のない無限改善や過学習を招きやすい   |
| P-4 | facet 製スキル（AI Orchestra 管理）と導入先独自スキルで反映先が異なる        |

## 3. スコープ

### 3.1 In Scope

- 二軸評価（自己申告 ＋ 機械計測）によるスキル実行品質の計測（B）
- 二層ループ（オンライン軽量収集 ＋ オフライン反復改善）（B）
- 改善の反映（非 facet=lessons 注入 / facet=承認付き昇格）（B）
- `skill-review-policy` への「4 視点網羅オプション」追記（A の最小拡張）

### 3.2 Out of Scope

| 項目                               | 理由                                       |
| ---------------------------------- | ------------------------------------------ |
| 成果物セルフレビューの本格自動実行 | `skill-review-policy` / `/review` と重複   |
| facet への完全自動昇格（無人）     | 品質ガバナンス上、当面は人間承認ゲート必須 |
| スキル外（エージェント本体）の改善 | 対象はスキル単位に限定                     |

## 4. 機能要件（FT）

| ID    | 要件                                                                                               | 優先   |
| ----- | -------------------------------------------------------------------------------------------------- | ------ |
| FT-01 | スキル発火を検出し、対象スキル名を特定できる                                                       | must   |
| FT-02 | スキル実行ごとに二軸テレメトリ（自己申告＋機械計測）を `metrics/<skill>.jsonl` に記録できる        | must   |
| FT-03 | 実行の学びを `lessons/<skill>.md` に追記できる                                                     | must   |
| FT-04 | スキル発火前に該当スキルの lessons をコンテキストへ注入できる                                      | must   |
| FT-05 | スキルごとに `[critical]` チェックリスト（最小成功条件）を定義でき、全達成で初めて成功と判定できる | must   |
| FT-06 | オフライン反復ループを手動コマンド / スケジュール / lessons 閾値で起動できる                       | must   |
| FT-07 | 固定シナリオを新規サブエージェントで並列ディスパッチし、学習バイアスを避けて評価できる             | must   |
| FT-08 | 二軸 judge でスコアリングし、1 反復 1 テーマの改善案を生成できる                                   | must   |
| FT-09 | 停止条件＋3 ガード（発散 / 過学習 / コスト / 最大反復）で暴走を止められる                          | must   |
| FT-10 | 非 facet 製スキルは lessons/SKILL.md へ diff 提示＋人間承認で反映できる                            | must   |
| FT-11 | facet 製スキルは facet 昇格（人間承認＋`facet build` 連携）で反映できる                            | must   |
| FT-12 | `skill-review-policy` に 4 視点（Security/Perf/Quality/a11y）網羅オプションを追記する              | should |

## 5. 非機能要件

| ID    | 要件                                                                                           |
| ----- | ---------------------------------------------------------------------------------------------- |
| NF-01 | オンライン層はスキル実行のレイテンシ・コンテキストを著しく増やさない（軽量・非同期追記中心）   |
| NF-02 | オフライン層はコスト上限・最大反復上限を持ち、無限ループに陥らない                             |
| NF-03 | 改善反映には人間承認ゲートを必須とし、無人での破壊的変更を行わない                             |
| NF-04 | 既存基盤（`context-sharing` の inject/capture、`quality-gates`）を流用し、新規配線を最小化する |
| NF-05 | facet 製/非 facet 製の判別が誤っても、誤った反映先へ書き込まない（安全側にフォールバック）     |

## 6. 受け入れ基準

- スキルを実行すると `metrics/<skill>.jsonl` に二軸データが 1 行追記される。
- 同一スキルを再実行すると、直前の lessons が発火前コンテキストに注入されている。
- `[critical]` 未達のスキル実行が「成功」と記録されない。
- オフラインループが停止条件 or いずれかのガードで必ず終了する。
- lessons 蓄積量がしきい値を超えると、オフラインループが起動する（FT-06）。
- 固定シナリオが新規サブエージェントで並列ディスパッチされ、評価実行が直前の履歴に汚染されない（FT-07）。
- 1 反復で生成される改善案が単一テーマに限定されている（FT-08）。
- 改善案の反映は、人間が diff を承認しない限りファイルへ書き込まれない。
- facet 製スキルの改善は `facet build` を経由して配布物へ反映される。

## 7. 評価軸の定義（二軸）

| 軸               | 指標                                                            | 取得元          |
| ---------------- | --------------------------------------------------------------- | --------------- |
| 自己申告（定性） | 新規不明瞭点の有無 / 裁量補完の回数 / 再試行回数                | 実行主体の申告  |
| 機械計測（定量） | `tool_uses` / `duration_ms` / `[critical]` チェックリスト達成率 | hook の機械収集 |

> 成功判定は **`[critical]` 全達成が前提**。定性・定量はスコアリングと改善テーマ選定に用いる。
