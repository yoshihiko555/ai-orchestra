## 比較の限界

1. baseline の根拠の照合は、成功した Read の記録だけを用いる近似である。Grep / Glob で見た範囲は記録せず、Read の表示切詰めとも完全に一致する保証はない。
2. baseline ではパス単位の除外を強制せず、prompt で評価資料を読まないよう指示している。agent は deny で `docs/evaluation/repo-understanding/**` を除外している。今回保存した結果も今後の評価資料に含まれるため、baseline では正解を参照した形跡を抜き取り時に確認する必要がある。
3. 集計対象の試行回数は 1 回であり、繰り返し実行によるばらつきは測っていない。4 問＋16 問の分割は、独立した 2 回の全問評価を意味しない。
4. 採点は Claude が行っている。manager による L-01 の確認はあるが、人の最終確認は PR で行う予定である。
5. `verified` はファイルの実在・行範囲・読取記録を確かめるものであり、主張の意味的な正しさまでは保証しない。

baseline の未確認割合約 12%（11/92）と agent の 0% の差は、そのまま「でっち上げの多さ」の差を示すものではない。
baseline の読取範囲の記録が近似であることと、意味的な正しさを測っていないことを踏まえて解釈する。
